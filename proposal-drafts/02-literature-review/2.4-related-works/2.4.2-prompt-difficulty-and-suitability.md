### 2.4.2 Prompt difficulty and suitability

The predictor will need model-specific evidence, not merely a generic label that a request is easy or hard. The following studies distinguish external success prediction, answer-time confidence, hidden-state methods and compute allocation. Only signals available before dispatch will be assumed usable for ordinary hosted APIs.

**Fly-swat or cannon** (Šakota et al., 2024). *peer-reviewed.* Per-model success meta-model and assignment will be considered in relation to Scored language-model tasks. FORC ("fly-swat or cannon") predicts, from the text of a query alone, whether each of several candidate language models will answer it correctly. An assignment step then sends every query to the model that best trades predicted success against API price, within a user budget.

The relevant boundary is pool/price assumptions; no gateway recovery claim. Its per-model formulation will guide the distinction between generic difficulty and suitability. Prediction will remain separate from hard capability filtering.

**Confidence elicitation** (Xiong et al., 2024). *peer-reviewed.* Prompting, repeated sampling and aggregation will be considered in relation to Reasoning/knowledge tasks. The paper evaluates how well LLMs can report how likely their own answers are to be correct when only black-box access is available (no logits, no fine-tuning). It organises the methods into prompting, sampling and aggregation, and tests them for calibration and for predicting failures.

The relevant boundary is answer-time confidence differs from routing-time prediction. Calibration will be measured directly. The system will not interpret confident wording in a generated response as a verified success probability before generation.

**Confidence tokens** (Chuang et al., 2025). *peer-reviewed.* Self-reflection training for confidence signalling will be considered in relation to Question-answering tasks. Self-REF fine-tunes a small local LLM to append a "confident" or "unconfident" token after its answer. The probability of the confident token is used as a correctness score: when it is low, the query is sent on to a larger, costlier model or the system abstains.

The relevant boundary is changes model behaviour; not a free gateway feature. This will distinguish response confidence from a lightweight external suitability predictor. The project will avoid making underlying-model training a prerequisite.

**Input-adaptive computation** (Damani et al., 2025). *peer-reviewed.* Predict reward distributions for compute allocation will be considered in relation to Reasoning and code tasks. The paper trains a lightweight predictor that reads a query and estimates how much extra computation would improve the answer, then spends a compute budget where it helps most. It uses this in adaptive best-of-k sampling and in routing between a cheap and an expensive decoding procedure.

The relevant boundary is decode-budget allocation differs from model selection. The study will treat difficulty as a feature whose usefulness depends on the candidate and resource decision, rather than as a complete routing policy.

**Hidden-representation difficulty** (Zhu et al., 2025). *peer-reviewed.* Initial hidden-state value estimation will be considered in relation to Textual and reasoning tasks. The paper estimates how hard a question is for a specific LLM using only that model's hidden state after reading the question, with no tokens generated. The difficulty estimate then decides how much repeated sampling (self-consistency, best-of-N, self-refine) to spend per question.

The relevant boundary is requires target-model internal representations. Closed hosted APIs will not be assumed to expose the needed state. The proposed predictor will use features available at the gateway boundary.

**Uncertainty and item difficulty** (Zotos et al., 2025). *peer-reviewed.* Text and uncertainty features in a regressor will be considered in relation to Multiple-choice datasets. The paper predicts how hard multiple-choice exam questions are for students, using a small Random Forest regressor over two kinds of features: a vector representation of the question and the uncertainty that several LLMs show when they answer it. The uncertainty features clearly improve over text alone.

The relevant boundary is human item difficulty differs from model suitability. The evaluation will distinguish a task label from observed per-model quality and avoid treating an educational difficulty correlation as evidence of routing gains.

Taken together, these studies will guide an explicit baseline or design boundary. The proposal will test the selected mechanism under one frozen data and policy contract. It will not combine incompatible metrics or select a favourable operating point from each study as though they described one experiment.
