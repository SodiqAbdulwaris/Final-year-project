### 2.4.4 Cost reduction and cascades

Cost can be reduced through model choice, repeated sampling, prompt compression or skipped execution. The project will evaluate constrained selection as the core mechanism. It will treat quality cascading as optional and will charge for every generation or verification call in that arm.

**Routing and cascading** (Dekoninck et al., 2025). *peer-reviewed.* Formal optimisation unifying model-selection strategies will be considered in relation to RouterBench and SWE-Bench. Model selection is framed as one optimisation problem: maximise expected answer quality under an expected-cost budget. The paper derives the optimal routing rule, the optimal cascading rule, and a hybrid, *cascade routing*, that can start with any model and keep re-routing after each answer.

The relevant boundary is estimator and optimisation assumptions. The formal distinction between routing and cascading will guide the policy variants. The project will measure predictor quality instead of assuming access to an accurate estimator.

**LLMLingua** (H. Jiang et al., 2023). *peer-reviewed.* Coarse-to-fine prompt compression will be considered in relation to Reasoning and long-prompt tasks. A method that shortens a long prompt by deleting the tokens a small language model finds predictable, so a black-box LLM sees far fewer tokens. Fewer input tokens mean lower API cost and lower latency.

The relevant boundary is input transformation can change task information. This is an alternative cost lever, not the core routing algorithm. The gateway will not silently compress client messages under a model-selection requirement.

**LongLLMLingua** (H. Jiang et al., 2024). *peer-reviewed.* Question-aware long-context compression will be considered in relation to Long-context evaluation tasks. An extension of LLMLingua to long prompts such as retrieved documents. Compression is conditioned on the user's question so that the parts relevant to it survive, and the surviving documents are reordered to avoid the "lost in the middle" effect. On several benchmarks the compressed prompt gave *better* answers than the full prompt at a fraction of the cost.

The relevant boundary is compression/task dependence. Its relationship to prompt length will inform the context-window filter, while router-managed context and compression will not be assumed to be accepted scope.

**BEST-Route** (Ding et al., 2025). *peer-reviewed.* Joint model and sampling-compute selection will be considered in relation to Scored generation tasks. A small proxy reward model picks the best sample.

The relevant boundary is repeated responses alter cost and latency. The experiment will account for all calls in any optional escalation arm. The core policy will select a feasible model before generation.

**Uncertainty-based cascades** (Gupta et al., 2024). *peer-reviewed.* Study deferral rules for generative models will be considered in relation to Generation benchmarks. A systematic study of how a small language model should decide to hand an input to a larger one. For classification, the small model's confidence works well. For text generation the output is a sequence of token probabilities, and the way these are summarised changes which queries are deferred.

The relevant boundary is sequence uncertainty is not generic correctness. This will motivate caution about cascade triggers. Operational retries will continue to use execution errors rather than a token-confidence threshold.

**Mixture-of-thought cascades** (Yue et al., 2024). *peer-reviewed.* Answer consistency across reasoning representations will be considered in relation to Reasoning benchmarks. A two-LLM cascade for reasoning questions.

The relevant boundary is multiple samples and verifier/task assumptions. This will be reviewed as optional quality escalation. Its repeated-generation budget will be kept separate from failure-recovery accounting.

Taken together, these studies will guide an explicit baseline or design boundary. The proposal will test the selected mechanism under one frozen data and policy contract. It will not combine incompatible metrics or select a favourable operating point from each study as though they described one experiment.
