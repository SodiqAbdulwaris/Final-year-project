### 2.4.5 Latency and load balancing

Llumnix migrates requests across serving instances and reports up to 36% cost savings at similar tail latency (Sun et al., 2024); Mooncake uses shared key–value cache infrastructure and reports 75% more requests on its real-workload experiment in the extended preprint (Qin et al., 2025). Both depend on engine and cluster control, so their results cannot be transferred to an API gateway. RouteBalance jointly considers quality, cost and load (Da & Kalyvianaki, 2026), countering a blanket novelty claim; its publication status remains unverified.

Sarathi-Serve interleaves chunked prompt processing with decoding, whereas DistServe separates these phases across resources (Agrawal et al., 2024b; Zhong et al., 2024). Vidur simulates serving performance (Agrawal et al., 2024c), PagedAttention manages cache memory (Kwon et al., 2023), and speculative decoding uses draft-and-verify generation (Leviathan et al., 2023). These optimise different stages and require different controls. Evaluation should separate first-token, completion and routing latency under a fixed backend configuration.
