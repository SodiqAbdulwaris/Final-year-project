## 3.8 Tools and Technologies

Table 3.7 lists the planned tools and the reason for each. Versions will be fixed and listed in the environment manifest.

**Table 3.7: Tools and technologies**

| Tool or technology | Purpose | Justification |
|---|---|---|
| Python and FastAPI | Gateway and common API | Asynchronous request handling and automatic input validation; same language as the machine-learning tools. |
| sentence-transformers and scikit-learn | Embeddings, classification and prediction | Lightweight and practical on laptop hardware; exact models chosen after testing. |
| k-NN index | Retrieval of similar scored requests | Simple, testable and supports the embeddings-off ablation; index type and k chosen on validation data. |
| Ollama | Local model serving | Straightforward on Windows laptops; vLLM can be tried if memory allows. |
| Provider APIs (capped) | Hosted model access | Small capped pilot only; provider and amount recorded before use. |
| PostgreSQL | Registry, attempts, accounting and experiment provenance | Transactions for concurrent budget reservations; relational integrity. |
| pytest and a fault-injection harness | Unit, integration and failure tests | Requirement-traceable tests; controlled injection of failures on local backends. |
| Git and GitHub | Version control | Versioned configurations and reproducible experiments. |
| Two RTX 4070 laptops (Lenovo Legion 7i, ASUS ROG Zephyrus G16) | Feature extraction, classifier, index and small local inference | Available to the team; memory and throughput will be measured separately. |
| GitHub Projects | Sprint backlog and tracking | Free for students; keeps backlog next to the code. |
| AI image generation (Codex) | Drawing the figures of this chapter from the team’s own written design descriptions | Speeds up diagram production; each figure was checked against its description and the use is declared in Appendix H. |

Tools such as Redis and Prometheus, and direct live collection of graphics-card and queue data, are not part of the committed core. They could be added later if a separate scope decision is made. The final environment record will state operating systems, driver and runtime versions and package versions, instead of calling a changing “latest” release reproducible.
