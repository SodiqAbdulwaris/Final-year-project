## 3.8 Tools and Technologies

**Table 3.3: Proposed tools and technologies**

| Role | Proposed technology | Purpose and qualification |
|---|---|---|
| Gateway | Python and FastAPI | Asynchronous request validation and common API; versions will be frozen. |
| Classification/prediction | sentence-transformers and scikit-learn | Lightweight features and candidate estimators; exact models/estimator TODO. |
| Retrieval | k-NN index | Historical similarity features; index implementation and k TODO. |
| Local serving | vLLM or Ollama | Small benchmark-covered model and failure tests; engine/version chosen after fit testing. |
| Hosted access | Selected provider APIs | Small capped pilot; provider/version TODO. |
| Persistence | Relational database | Registry, attempts, accounting and experiment provenance; engine TODO. |
| Testing | Unit/integration framework and controlled fault harness | Requirements traceability, concurrency and recovery verification; exact versions TODO. |
| Reporting | Markdown, tabular exports and Mermaid | Proposal, figures and reproducible result presentation. |
| Hardware | Desktop RTX 4070 and laptop RTX 4070 | Feature extraction, classifier, index and small local inference; memory and throughput measured separately. |

Redis/Prometheus and direct live GPU/queue collection will remain unresolved earlier proposals. Including them in past source documents will not constitute a current dependency. The final environment manifest will state operating systems, driver/runtime and package versions, rather than calling a changing latest release reproducible.
