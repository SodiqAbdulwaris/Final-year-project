### 3.6.5 Algorithm and Model Design

For request q and candidate model m, the predictor will estimate:

\[\widehat Q(m,q)=f(\mathrm{task},\mathrm{difficulty},\mathrm{similarity},\mathrm{model}).\]

Task and capability classification will be lightweight. Mandatory request fields will be filtered first; any additional capability requirements inferred during analysis will be re-applied before selection. A classifier will not weaken an explicit client restriction. Difficulty and similarity will be predictive features rather than independent proof of quality. Similarity features will be derived only from permitted training/historical outcomes. The estimator, training labels, calibration method and split protocol will remain TODO. A score will not be called a probability unless its label definition and calibration justify that interpretation.

Let E(q) be deployments passing capability, context, privacy, health and preliminary affordability rules. Let B_rem be the remaining permitted budget, D_rem the remaining deadline, and τ the minimum predicted quality. The feasible set will be:

\[F(q)=\{m\in E(q):\widehat Q(m,q)\geq\tau,\ \widehat C(m,q)\leq B_{rem},\ \widehat L(m,q)\leq D_{rem}\}.\]

The selected deployment will minimise expected cost among feasible candidates:

\[m^*=\operatorname*{arg\,min}_{m\in F(q)}\widehat C(m,q).\]

Predicted latency will break equal-cost ties, followed by a stable deployment identifier for reproducibility. Deadline semantics, cost-estimation conservatism and tie tolerance will be TODO before protocol freeze. Predicted feasibility will not guarantee observed quality or latency; those violations will be measured. Before execution, a conservative spending reservation based on input and output caps will supplement expected-cost ranking. If chargeable tokens cannot be bounded, hard-budget eligibility will require a conservative bound or rejection.

The weighted utility will be evaluated only as a comparator/variant:

\[U(m,q)=\alpha\widehat Q(m,q)-\beta\widetilde C(m,q)-\gamma\widetilde L(m,q).\]

Tildes will denote normalised cost and latency; scaling constants and weights will be selected on validation data only and will remain TODO. This comparator will still obey hard restrictions; inexpensive inference will not compensate for an unsupported capability or unauthorised spend.

```text
ROUTE(q, policy):
  validate client, payload, authorised endpoints and declared constraints
  initialise finite attempt allowance, deadline and request accounting
  while allowance remains and caller has not cancelled:
    E <- filter mandatory capability, context, privacy, health and budget rules
    features <- classify q and retrieve only permitted historical evidence
    E <- re-apply capability filters using the analysed requirements
    estimates <- predict quality, cost and latency for E
    F <- enforce predicted quality floor, cost cap and remaining deadline
    if F is empty: return explicit INFEASIBLE under the declared policy
    candidate <- cheapest feasible candidate with deterministic tie breaking
    atomically revalidate and reserve conservative attempt spend
    if reservation fails: return explicit budget/state error before dispatch
    consume one attempt allowance
    outcome <- execute with remaining timeout through candidate adapter
    reconcile known usage; retain reservation for unresolved possible charges
    record redacted estimates, timing, exclusions and health outcome
    if completed: return response
    if not retryable or unsafe to repeat or partial output delivered: return error
  return explicit EXHAUSTED or CANCELLED outcome
```

The infeasibility responses will be **reject**, **relax an explicitly soft preference**, or **request permission to exceed an applicable constraint**. TODO: select which responses the minimum viable product (MVP) will support and define their client contract. No path will silently relax a hard budget, capability or privacy rule.

Retry eligibility, attempt count, cooldown and breaker thresholds will remain TODO and [PROVISIONAL: revise after pilot]. Half-open probes will be bounded. Fallback will reconsider remaining resources and potentially consumed tokens rather than reusing the original budget. After delivery begins, the gateway will signal failure rather than silently stitching another model's stream onto it. Calls with unsafe or uncertain side effects will not be automatically repeated.

Monitoring will feed an offline calibration process. The update cadence and evidence policy will be TODO; logging will not be described as online adaptation. Quality-based cascading will remain a separate optional experiment after completed responses, and its verifier calls, costs and latency will be accounted for explicitly.
