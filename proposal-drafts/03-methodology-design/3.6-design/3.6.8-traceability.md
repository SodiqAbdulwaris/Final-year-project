### 3.6.8 Traceability of Requirements to Design and Tests

Table 3.5 begins the traceability matrix, linking requirements to the design elements that satisfy them and to the kind of test that will check them. Test identifiers will be assigned when the test plan is written, and the matrix will be completed in the final report.

**Table 3.5: Draft traceability of requirements to design and tests**

| Requirement | Design element | Planned test |
|---|---|---|
| FR-01, FR-02 | Gateway and validation (Figure 3.3) | API contract and authentication tests |
| FR-03 | Registry; Model and Deployment relations (Table 3.4) | Registry and constraint tests |
| FR-04, FR-09 | Eligibility filter; infeasibility branch (Figure 3.8) | Filter unit tests; infeasible-request cases |
| FR-05 to FR-08 | Prompt analyser, retriever, predictor, selector (Figure 3.5; Section 3.6.5) | Held-out ablation and selection tests |
| FR-10 | Budget accountant; Reservation relation (Table 3.4) | Concurrent-reservation assertions |
| FR-11 to FR-14 | Provider adapter, health tracker, execution controller (Figures 3.5 and 3.7) | Fault-injection tests |
| FR-15 to FR-17 | Decision log; operator view (Figure 3.10) | Redaction and export tests |
| FR-18 | Deployment (Figure 3.4) | Deployment checklist run by a second member |
| NFR-01 to NFR-03 | Selector; evaluation pipeline (Figure 3.11) | Quality, cost and overhead evaluation |
| NFR-04, NFR-05 | Reliability controller; budget accountant | Failure-injection and violation tests |
