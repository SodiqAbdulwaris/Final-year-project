## 3.7 Data Collection and Preparation

RouterBench and LLMRouterBench are the candidate sources of already-scored model outputs (Hu et al., 2024; Li et al., 2026). The team will inspect task identifiers, prompts, model revisions, scores, token counts and cost fields before choosing a shared evaluation subset. The evaluated pool will contain three to four models covering a small local option, a mid-tier option and a frontier option. Names will be fixed once aligned scored outputs for the same requests are confirmed, and public availability of a model in a benchmark does not by itself show that its outcomes line up with the others. Table 3.6 lists the planned controls.

**Table 3.6: Data preparation controls**

| Data stage | Planned control |
|---|---|
| Provenance | Record the official release, revision, file hashes, model IDs, prompting settings and label definitions. |
| Coverage | Verify aligned per-request outcomes for the chosen models, spanning a small, a mid-tier and a frontier option. |
| Licence | Check dataset and component terms separately from code licences (Appendix G). |
| Cleaning | Detect duplicate and near-duplicate prompts, invalid scores, missing outcomes and inconsistent token or cost units. |
| Split | Group related requests and keep duplicates in one partition; training, validation and test partitions fixed before tuning. |
| Features | Fit classification, the retrieval index, normalisers and calibration only on training and validation partitions. |
| Evaluation | Keep evaluated outcomes out of training and retrieval for those requests; reveal labels only for scoring. |

A benchmark’s own split will not automatically become the study protocol. A tuning pilot will be kept separate from the untouched test partition. If aligned outcomes across models are not available, the limitation will be recorded and the gaps will not be filled with unrelated benchmark averages. No raw benchmark data will be redistributed with the report. RouterBench has an MIT code licence, but the inspected data card did not establish a dataset-level redistribution grant, and the MIT badge on LLMRouterBench does not settle its missing data licence text; dataset use will be cleared in Appendix G before data is used. New hosted calls will be limited to a capped pilot, with the provider and amount recorded before the pilot starts. A quantised local model and a historical hosted version of a similarly named model are separate configurations and are not assumed to share quality labels.
