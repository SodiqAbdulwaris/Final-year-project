## 1.11 Definition of Operational Terms

| Term | Meaning in this project |
|---|---|
| Ablation | An evaluation that removes or isolates one component to assess its contribution. |
| Baseline | A simpler comparison policy, such as a fixed model, the cheapest eligible model or a rule-based selector. |
| Calibration | Agreement between predicted and observed quality or success on comparable held-out requests. |
| Circuit breaker | A controller that temporarily blocks calls to a deployment after qualifying failures and allows bounded recovery probes. |
| Eligibility constraint | A hard requirement, such as capability, context window, privacy or budget, that a deployment must meet before it can be selected. |
| Embedding-derived evidence | Features obtained by comparing a request with previously scored requests using vector representations. |
| Held-out test set | Requests excluded from fitting and tuning and reserved for final evaluation. |
| Hybrid routing | A routing approach that combines task classification with embedding-derived suitability evidence. |
| Large language model (LLM) | A model that processes and generates natural language in response to input. |
| LLM request router (gateway) | A service between client applications and model deployments that selects a deployment for each request. |
| Model deployment | A specific hosted endpoint or local serving instance able to process requests. |
| Model suitability | The predictor’s estimate of how well a candidate deployment will meet a particular request. |
| Operational fallback | A new attempt through another eligible deployment after a defined execution failure. |
| Quality cascade | An optional escalation to another model after a completed answer is judged inadequate; distinct from operational fallback. |
| Routing overhead | Time spent in gateway processing and selection, apart from model generation. |
