## 1.3 Aim and Objectives

**Aim:** To design, implement and evaluate a prompt-aware LLM request-routing gateway that selects an eligible hosted or locally served model deployment for each request under quality, cost, latency and privacy constraints, with bounded operational fallback.

**Objectives:** the project will achieve the aim through the following objectives, each within the project timeline set out in Section 3.1.

1.  To specify the functional, policy, security and reliability requirements of the gateway and trace each to an acceptance test.
2.  To design and implement a unified gateway with request validation, a registry of model deployments, configurable eligibility rules, routing policies and operational logging.
3.  To develop a lightweight model-suitability predictor that combines task classification with embedding-derived evidence, and to assess each component by ablation on held-out scored requests.
4.  To implement a constrained selector and compare its quality, cost and latency with fixed-model, cheapest-eligible, rule-based and lightweight learned baselines.
5.  To integrate hosted and local deployments with health tracking, circuit breakers and bounded fallback that respects hard constraints.
6.  To deploy the gateway in a documented environment and evaluate its correctness, overhead and resilience under normal operation, controlled concurrency and injected failures.

Each objective yields a specified artefact and a measurable comparison. No objective requires a positive result: a simpler method that matches the hybrid is a reportable outcome. Numeric targets and the quality margin will be fixed after a pilot and before the held-out results are examined.
