# Abstract

Applications that use large language models (LLMs) can reach them through hosted services or locally run models, and these options differ in price, response time, capability and availability. Sending every request to one fixed model ignores these differences, and routing studies that compare methods offline on stored outputs do not show whether a working system enforces budget, capability and privacy limits or recovers when a model fails. For Nigerian developers, dollar-priced services and rules on moving personal data abroad make the choice more consequential. This project will design, implement and evaluate a prompt-aware request-routing gateway that selects an eligible hosted or local model for each request under quality, cost, latency and privacy constraints, with bounded fallback, using health tracking and circuit breakers, when a model fails. The work will follow an iterative development approach. The gateway will first remove models that fail hard requirements, then use lightweight task classification and similarity to previously scored requests to estimate how well each remaining model suits the request, and choose the cheapest model that meets the quality and deadline requirements. Development will reuse public scored benchmark outputs where licences allow, run small local models on two RTX 4070 laptops and cap hosted calls. The hybrid approach will be compared with fixed-model, cheapest-eligible, rule-based and simpler learned routers, with each component tested by ablation. Evaluation will measure quality, cost, latency, calibration, constraint violations, gateway overhead and request completion under injected failures, with the protocol fixed before the held-out results are examined. At this proposal stage no results exist. The expected outputs are a requirements specification, a deployed gateway, a documented comparison and reproducible evaluation evidence. A simpler router that matches the hybrid will be an acceptable finding, so the study can show when added routing intelligence is worth its overhead.

**Keywords:** Constraint-aware selection; Large language models; Operational fallback; Prompt-aware routing; Request-routing gateway.
